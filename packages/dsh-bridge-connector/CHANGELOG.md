# Changelog

## 0.7.4 — 2026-11-28

**新：注入审计账本**
- 每次注入真的进系统提示词，都留一条事件：`due`（这一轮定了带哪几篇）、`render`（真被提示词段取走）、`rollback`（投递失败退回）。定了但没取走时只有 `due` 没有 `render`，异常一眼看得出来。
- `add` / `clear` / `refresh` 操作本身也入账，带 itemId、scope、标题、路径、节奏参数。
- 落 `~/.dsh-bridge/injection-ledger.jsonl`，一行一条 JSON，只追加；只记元信息，不记正文。
- 新增 `GET /inject/ledger?limit=N`（默认 50，上限 2000）。

**修**
- 账本写失败原来是空 catch 吞掉，现在通过 `onError` 报到 DSH 日志，注入本身不受影响。

## 0.7.3 — 2026-11-23

- 修：设置页的快捷键输入框只在刚录完时显示组合键，重开页面就空着，看着像没绑上。现在渲染时用当前绑定回填，只有「清除」才留空。
- 发版流程换成 GitHub Actions + OIDC：打 `v*` tag 自动发布，不再手工 `npm publish`（手工那条会先返回 202、约五分钟后才真正落地，容易误判失败）。
## 0.7.2 — 2026-11-22

- 代码与 0.7.0 / 0.7.1 相同。
- 0.7.0 与 0.7.1 在 npm 上都只落了元数据、没有 tarball（CLI 发布被 2FA 暂存，装不上），版本号作废。
- 改成 GitHub Actions + OIDC 的 trusted publishing 发布，不再经过手工 2FA 暂存。
## 0.7.1 — 2026-11-22

- 代码与 0.7.0 完全相同，只把版本号递增一位。
- 原因：0.7.0 在 npm 上是「暂存」状态（PUT 返回 202，只有元数据、没有 tarball，装不上），撤回后 npm 不允许再用同一个版本号 —— 版本一经撤回就作废，只能换个号重发。
## 0.7.0 — 2026-11-22

**新：会话转录（默认关，插件设置里开）**
- DSH 这头的连接器接管「会话写进库」：对话原文、用过的工具名、工具结果，按会话按天落到 `记录/日志/agent.dsh-raw/<日期>/会话-<短id>.md`
- 工具参数不记；成功的工具结果单条截到 2000 字并注明截断，**失败的结果整条保留**（堆栈切一半等于白查）
- 轮次保留成路标（`第 N 轮开始/结束`），出事时按轮次直接跳
- 实时事件直写 + 启动按偏移补漏，`seq` 去重；库路径没到之前一个事件都不消费，路径到了再一次性补
- 库路径落盘，重启不用等插件重推

**修**
- 快捷键绑定没落盘：`setHotkeys` 只改内存，补上 `hotkeyManager.save()`，否则重启就回默认
- 设置页录完组合键点「设为」后输入框被清空：状态提到重建之外，设为/恢复默认都会回填
- 「已绑定」显示会回落到默认键（只读 `getHotkeys` 会把有默认键的命令显示成「无」）

**撤**
- 审批三档那套（只提示 / 面板批准 / 自动放行）已下线：DSH 的 MCP 工具根本不会申请审批，那套永远触发不了
## 0.6.2 — 2026-11-21

**新端点**
- `GET /usage?sessionId=` — 读会话日志里的 token 用量，给面板算「上下文占用」

**新**
- 面板输入条显示上下文占用（超 70% 变黄、90% 变红），只在绑会话 / 一轮结束 / 窗口拿回焦点时刷，不轮询
- 注入节奏可控：每 N 轮带一次、一共带 M 次，不再是每轮都带
- 当前笔记改按「可见的那个标签页」认，不再按焦点历史猜；切标签页立刻跟着换

**改动**
- 「当前笔记」只给坐标（路径 / 大小 / 行数 / 改动时间），不再带光标位置和所处小节；要精确定位用标记
- 标记四个动作：打点（只一个）、区域（可多块）、清除光标处那一个、全部清除

**没上线**
- 审批三档（只提示 / 面板批准 / 自动放行）已撤：DSH 的 MCP 工具根本不会申请审批，那套永远触发不了
## 0.4.0 — 2026-11-08

**新端点**
- `GET /workspaces` — 读 DSH 的工作区列表
- `POST /workspace {path,title}` — 注册一个目录为工作区
- `GET /transcript?sessionId=&limit=` — 读会话最近的对话（面板 reload 后靠它恢复）

**改动**
- `/sessions` 增加 `title`（从 session 日志的 `session/title` 事件读，投影里是空的）、`workspaceTitle`、`workspacePath`、`archived`、`blank`、`parentSessionId`
- `/task` 投递时给消息加 `【Obsidian】` 来源标记；支持 `mode: steer`
- `/session` 支持 `workspaceId`；`workspaceId` 与 `cwd` 二选一（同时传 DSH 会拒）
- 只给最近 60 个会话读标题，其余降级（标题要解压日志，几百个全读会卡首屏）

## 0.3.0 — 2026-11-02

**注入改成实时跟随（行为变更）**
- `/inject` 现在接受 `path` + `absPath`：只记路径，系统提示词每轮按 `mtime + size` 读磁盘最新内容
- 笔记改了，注入下一轮就跟着变，不用重新注——读到的是磁盘上的那一份，未保存的改动不会被注入
- 落盘只存路径（`~/.dsh-bridge/injections.json`），不存正文；正文每轮实时读
- 文件读不到时用最后一次读到的内容；从没读到过则明确写成「（文件读不到：xxx）」，不给空串
- 实时内容同样受 512KB/篇 预算约束，超了截断并注明
- 选区等不在文件里的内容仍作为「附加内容」拼在正文后，标成`【选中内容】`

**兼容性**
- 需要配套 Obsidian 侧 Bridge 插件 **0.3.0+**（它改成传路径）
- 旧客户端仍可传 `content`，走纯正文快照模式（老行为）

## 0.2.0 — 2026-10-31

首个公开版本。

**功能**
- 会话：列出 / 新建 / 向指定会话发消息
- 注入：最多 10 篇笔记挂进系统提示词段 `bridge:context`（order 250），单篇 512KB 预算，同标题覆盖
- 注入开关：落盘到 `~/.dsh-bridge/state.json`，DSH 重启后保持上次状态

**加固**
- 请求入口兜底：畸形请求行（如 `GET //`）回 400，不再把整个 DSH 进程打挂
- 请求体超限回 413（以前直接掐连接，调用方只看到 ECONNRESET）
- `/inject/clear` 收到坏 JSON 回 400，不再静默清空全部注入
- 单篇注入超 512KB 回 413（它在系统提示词里，每轮都要重发）
- 候选会话缺 `sessionId` 时回 409，不再 500 泄露内部异常

**删除**
- 没人消费的「按会话排队」通道（`take()` 无调用点，队列只进不出会漏内存），现在只有「当前注入」这一条语义
- `pre-step.mjs` 整份死代码及其测试
